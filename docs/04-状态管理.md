# 状态管理

> **主链路不使用 Pinia**（2026-09 对齐）：引擎状态以 **instanceState 工厂（`src/composables/instanceState.ts`）**
> 创建四份实例级状态，由 `SchemaEngine.vue` 创建、`SchemaContextProvider.vue` 经 `provide` 注入
> （`SCHEMA_META_KEY` / `RECORD_STATE_KEY` / `UI_STATE_KEY` / `RUNTIME_CONTEXT_KEY`），
> 组合式函数通过 `useSchemaMeta()` / `useRecords()` / `useUi()` / `useRuntimeContext()` 的 `inject` 访问。
> 同页多实例各自持有独立状态，天然支持多实例隔离。
>
> `src/stores/` 下四个 Pinia store 中，仅 **`runtimeCacheStore` 仍在主链路**
> （`FkSelector` / `ValueRenderer` / `CreateView` 用它缓存候选值与公式结果，
> 这是宿主需要安装 Pinia 的原因）；`schemaMetaStore` / `recordStore` / `uiStateStore`
> 已是 0.1 期遗留实现，主链路零引用（仅存量单测覆盖）。下文 §1–§3 按遗留实现存档，
> §4 为在用的 runtimeCacheStore；遗留三 store 的移除属破坏性变更，规划在 0.3.0 评估。

## 0. instanceState 主链路（当前实现）

**文件**: `src/composables/instanceState.ts`

| 工厂 | 注入键 | 访问器 | 职责 |
|------|--------|--------|------|
| `createSchemaMetaState()` | `SCHEMA_META_KEY` | `useSchemaMeta()` | Schema / 视图配置 / 权限真源（同 §1 遗留版字段面） |
| `createRecordState()` | `RECORD_STATE_KEY` | `useRecords()` | 记录 / 草稿 / 查询状态 + 引擎级 undo/redo 双栈（同 §2，含 docs/19 H3 history 成员） |
| `createUiState()` | `UI_STATE_KEY` | `useUi()` | 视图模式 / 选中行 / 弹窗 / 全局消息（同 §3 遗留版字段面） |
| `createRuntimeContextState()` | `RUNTIME_CONTEXT_KEY` | `useRuntimeContext()` | 运行时全局上下文与角色（roleBased 权限消费，docs/19 G3） |

`inject` 未命中时抛错——引擎状态只能在被 `SchemaContextProvider` 覆盖的组件树内访问，
不提供全局兜底单例，这是多实例隔离的实现基础。

## 状态隔离原则

- **多实例隔离**：instanceState 按 `SchemaEngine` 实例创建并 `provide`，同页多实例互不串扰；`inject` 未命中即抛错，不存在全局兜底单例
- **records** vs **drafts**：正式记录和草稿完全隔离，草稿操作不污染正式数据
- **queryState** 唯一真源：filters / sort / pagination 只在一个地方维护
- **dialogState** 唯一真源：全局弹窗状态由 uiState 统一管理
- 模块切换时对实例状态执行 `$reset()`（遗留 Pinia store 同理），防止旧数据泄露
