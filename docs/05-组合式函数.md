# 组合式函数

## 1. useSchema

**文件**: `src/composables/useSchema.ts`

模块加载与视图管理的核心 composable。

**全局状态**: `loadingModuleId` — 模块级异步竞态保护 ref。每次 `loadModule` 先设置 `loadingModuleId`，所有异步返回点检查是否匹配，不匹配则丢弃结果。

**返回值**:

| 属性 | 类型 | 说明 |
|------|------|------|
| `isSchemaLoaded` | `ComputedRef<boolean>` | Schema 是否加载完成 |
| `currentSchema` | `ComputedRef<ModuleSchema \| null>` | 当前模块 Schema |
| `currentViewConfig` | `ComputedRef<UserViewConfig \| null>` | 当前视图配置 |
| `currentPermissions` | `ComputedRef<ModulePermissions \| null>` | 当前权限 |
| `visibleFields` | `ComputedRef<FieldSchema[]>` | 可见字段列表 |
| `schemaError` | `ComputedRef<string \| null>` | 加载错误 |
| `isSchemaLoading` | `ComputedRef<boolean>` | 加载中 |
| `viewMode` | `ComputedRef<ViewMode>` | 当前视图模式 |
| `loadModule(moduleId)` | `async` | 加载模块 |
| `setViewMode(mode)` | `function` | 切换视图模式（带权限检查） |
| `saveViewConfig(config)` | `async` | 保存视图配置 |

**loadModule 流程**:
```
1. 设置 loadingModuleId
2. $reset() 所有 Store
3. 并行加载：
   - schemaService.loadModuleSchema(moduleId)
   - schemaService.loadModulePermissions(moduleId)
   - userViewConfigService.load(moduleId)
4. 检查 loadingModuleId 是否仍然匹配
5. 写入 schemaMeta.setSchema / setPermissions / setViewConfig
6. 设置默认 viewMode
```

## 2. usePermission

**文件**: `src/composables/usePermission.ts`

权限控制 composable。

**返回值**:

| 属性 | 说明 |
|------|------|
| `canView` | 查看权限 |
| `canCreate` | 新增权限 |
| `canEdit` | 编辑权限 |
| `canDelete` | 删除权限 |
| `canExport` | 导出权限 |
| `canConfigure` | 配置权限 |
| `isFieldVisible(fieldKey)` | 字段是否可见（检查 visible + permission.visible） |
| `isFieldEditable(fieldKey)` | 字段是否可编辑（检查 readonly + permission.editable + canEdit） |
| `filterVisibleFields(fields)` | 过滤可见字段 |

全部从 `schemaMeta.permissions` 和 `schemaMeta.getField()` 读取。

## 3. useCellEdit

**文件**: `src/composables/useCellEdit.ts`

单元格编辑处理。

**onCellEdit(payload: CellEditPayload)**:
```
1. 检查是否为公式字段 → 跳过
2. uiState.setEditingCell({ rowId, field })
3. recordService.patchField({ moduleId, recordId, field, value, expectedVersion })
4. 成功 → updateRecordField(rowId, field, value, newVersion)
       → history.pushCellEdit(...)（docs/19 H3:服务端确认成功后才入栈,失败不留幻影条目）
5. 失败 → VERSION_CONFLICT → 刷新后重试一次 / openDialog；其他 → showMessage
6. finally → uiState.setEditingCell(null)
```

撤销/重做能力已上提至引擎级 `useRecordHistory`（见 §8）。

## 4. useFormula

**文件**: `src/composables/useFormula.ts`

公式引擎。依赖 mathjs 的 `evaluate()` 进行表达式计算。

**核心能力**:

| 方法/属性 | 说明 |
|-----------|------|
| `formulaConfigs` | 当前模块的公式字段配置列表 |
| `hasCycleError` | 循环依赖检测结果 `{ hasCycle, cyclePath }` |
| `evaluateAllFormulas(fields)` | 对 fields 执行全部公式，拓扑排序后依次 safeEval |
| `getEvaluationContext(fieldKey, recordId?)` | 获取公式求值上下文（表达式/依赖值/结果） |
| `updateFormulaResult(fieldKey, recordId, result)` | 缓存公式结果 |
| `clearCache()` | 清空公式缓存 |

**类型安全**: `safeEval` 用 try/catch 包装，错误返回 `{ __formulaError: message }`。`formatFormulaResult` 根据 resultType 转类型。

**精度**: `cleanPrecision` 保留 10 位小数精度。

**循环检测**: `detectCycle` DFS 遍历依赖图，检测是否有环。

## 5. useDraftLifecycle

**文件**: `src/composables/useDraftLifecycle.ts`

草稿生命周期管理。

**buildContext(lockedColumns)**:
返回 `DraftLifecycleContext`：`{ formulasEnabled, formulaFields, aggregationFields, lockedColumns }`

**applyDefaults(context, targetIndex)**:
1. 遍历 visibleFields，若 field 值未定义：
   - 有 `defaultValue` → 设置默认值
   - date/datetime 有 `defaultDateOffset` → 计算偏移日期
2. locked 列 + 非首行 → 自动复制上一行 locked 字段值

**fillLockedValues(context)**:
遍历所有行，locked 列为空的复制上一行值。

**evaluateFormulas(context, rowIndices?)**:
对指定行（默认全部）执行公式计算，比较计算前后值，有变化则 `updateDraftField`。

**computeAggregations(context)**:
计算草稿行的聚合值（sum/average/count/max/min），生成 `AggregationValue[]`。支持 `countCondition`（empty/notEmpty）和 `treatAsEmpty` 配置。

**isFieldEmpty(fieldKey, value)**: 检查值是否为空（null/undefined/''/treatAsEmpty 列表中）。

**formatDateValue(field, offsetDays)**: 根据 `defaultDateOffset` 计算日期字符串。

## 6. useAggregation

**文件**: `src/composables/useAggregation.ts`

列表数据的聚合计算。

**compute(records: RecordEntity[])**: 对 `sum/average/count/max/min` 字段计算聚合值，返回 `AggregationItem[]`。

支持 `countCondition`（empty/notEmpty）区分计数条件，`treatAsEmpty` 自定义空值集合。

## 7. useDynamicMax

**文件**: `src/composables/useDynamicMax.ts`

动态最大值约束检查。

**calculateMaxValue(fieldKey, recordFields)**: 计算 `sourceField × ratio` 作为最大允许值，判断当前值是否超限。

**validateField(fieldKey, newValue, recordFields)**: 字段变更时校验新值是否超限。mode 为 `soft` 时 `requireConfirm=true`。

返回 `DynamicMaxResult`：`{ maxValue, isExceeded, message, requireConfirm, originalValue, targetValue }`。

**messageTemplate 支持**: `{max}`、`{current}`、`{ratio}` 占位符替换。

## 8. useRecordHistory

**文件**: `src/composables/useRecordHistory.ts`

引擎级记录历史（docs/19 H3）：undo 栈自 useCellEdit 上提的实例级 history API。

**入栈粒度 = 一个用户动作**，一个 `HistoryEntry`（type + changes/createdRecords + timestamp）：

| 方法 | 说明 |
|------|------|
| `pushCellEdit(change)` | 行内/卡片单格编辑入栈；服务端确认成功后调用 |
| `pushBatchEdit(changes)` | 批量编辑入栈；整批一个条目，撤销/重做整批回放 |
| `pushCreate(records)` | 创建入栈（快速创建/创建视图保存）；记录须能在实例列表定位，否则跳过 |
| `undo()` | 撤销一个动作：本地回放逆向并转入 redo 栈；栈空返回 undefined |
| `redo()` | 重做：正向重放并转回 undo 栈；栈空返回 undefined |
| `canUndo` / `canRedo` | ComputedRef，联动 `RecordState` 双栈 |

**语义约定**:
- 新动作入栈（`pushHistory`）清空 redo 栈 —— 分叉历史失效。
- 回放是**本地内存操作**：字段变更回填值与乐观锁版本；`'create'` 撤销仅把记录移出
  实例列表（引擎无 delete 服务，刷新后以服务端数据为准）。
- FK 快速新建创建的目标模块记录不在当前实例列表中，`pushCreate` 跳过不入栈（无法回放）。
- 消费入口：ListView 工具栏「撤销/重做」按钮、`SchemaEngine.defineExpose` 的
  `undo/redo/canUndo/canRedo`（宿主可编程触发）。
- 双栈与本地记录原语（`removeRecordLocal`/`insertRecordLocal`）挂在 `RecordState`
  （docs/04 §2），上限各 50。
