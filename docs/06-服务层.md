# 服务层

## 架构设计

服务层采用 **接口 + 实现分离** 模式。每个 Service 模块定义 `I*Service` 接口，通过 `set*Service()` 注入实现（开发环境注入 Mock，生产环境注入真实 API），统一导出 `*Service` 代理对象。

```
组件/Composables → *Service (代理) → get*Service() → 实现 (Mock/API)
```

## 1. base.ts（基础设施）

**文件**: `src/services/api/base.ts`

| 函数 | 说明 |
|------|------|
| `setMockEnabled(enabled)` | 设置 Mock 开关 |

**文件**: `src/services/api/recordService.ts`

| 方法 | 说明 |
|------|------|
| `list(params: ListQueryParams)` | 分页查询记录 → `ApiResponse<RecordListResponse>` |
| `listFieldValueCandidates(params)` | 查询字段候选值 + 出现次数（用于表头内容筛选）→ `ApiResponse<FieldValueCandidateListResponse>` |
| `getDetail(moduleId, recordId)` | 获取单条记录 → `ApiResponse<RecordEntity>` |
| `patchField(params: PatchFieldParams)` | 更新单字段（乐观锁） → `ApiResponse<RecordEntity>` |
| `create(params: CreateRecordParams)` | 创建单条记录 → `ApiResponse<RecordEntity>` |
| `batchCreate(params[])` | 批量创建 → `ApiResponse<RecordEntity[]>` |

**PatchFieldParams**: `{ moduleId, recordId, field, value, expectedVersion, force? }` — 乐观锁版本号校验。

- `{ moduleId, field, keyword?, page, pageSize, filters? }`
- `filters` 为当前列表已生效的筛选条件（通常需要排除当前 field 自己的筛选），用于统计“在其他筛选条件下”的候选值及出现次数

**FieldValueCandidateListResponse**:
- `{ options: Array<{ value, label, count, disabled? }>, total, hasMore }`

## 7. Mock 层

## 服务注入流程

```
main.ts
  → import '@/services/mock/mockAdapter'  // 自动执行注入
    → setSchemaService(mockSchemaService)
    → setRecordService(mockRecordService)
    → setCandidateService(mockCandidateService)
    → setUserViewConfigService(mockUserViewConfigService)
    → setRelationService(mockRelationService)
```

**切换到真实后端**：只需将 `mock/mockAdapter` 替换为真实 API 适配器，注入相同接口的实现即可，上层代码零修改。

## Mock evaluateFilter 逻辑

Mock 层实现了完整的 `FilterClause` 解析：

```typescript
function evaluateFilter(clause: FilterClause, fieldValue: unknown): boolean {
  if (fieldValue == null) {
    return ['neq', 'notLike', 'notIn', 'notBetween', 'isNotNull'].includes(operator)
  }
  switch (operator) {
    case 'eq': return fieldValue === value
    case 'neq': return fieldValue !== value
    case 'like': return String(fieldValue).toLowerCase().includes(String(value).toLowerCase())
    case 'notLike': return !String(fieldValue).toLowerCase().includes(String(value).toLowerCase())
    case 'in': return values!.some(v => fieldValue === v)
    case 'notIn': return !values!.some(v => fieldValue === v)
    case 'between': return fieldValue >= values![0] && fieldValue <= values![1]
    case 'notBetween': return fieldValue < values![0] || fieldValue > values![1]
    case 'isNull': return fieldValue == null
    case 'isNotNull': return fieldValue != null
  }
}
```

多条件 AND 组合：`filters.every(clause => evaluateFilter(clause, recordField))`
