## 一、现状小结

**已达标**

- src/ 结构清晰：`engine/`、`composables/instanceState.ts`（多实例隔离核心）、`services/api/`（可注入 Service）、`services/mock/`、`editor/`、`styles/tokens.css`；公开入口 `src/index.ts` 干净。
- 双语 README 质量高且基本同步；docs/01-15 覆盖完整。
- TODO/FIXME 为 0，`any` 约 29 处且集中在 vxe-table 边界，可接受。
- type-check 链路已修复（project references + tsBuildInfoFile，`build` 走 `run-p type-check build-only`）。
- dist_backup_*、playwright-report、test-results 均已被 .gitignore 排除。

**主要缺口**

- 无任何 CI（无 .github/workflows）。
- 无 CONTRIBUTING / CHANGELOG / issue 与 PR 模板 / CoC。
- `.trae/` 目录（内部 AI 工作流文档、ps1 脚本）**已被 git 入库**；`src/stores/counter.ts` 为脚手架残留。
- 根目录 `引用指南.md`（29KB 实用内容）、`说明文档.md` 位置不当；docs/11-14 属内部过程文档，开源后易过期。
- e2e 分级脚本依赖 `pwsh scripts/run-e2e-tests.ps1`，Linux/macOS/CI 不可用。
- 单测只覆盖纯函数/服务层（8 个 spec）；instanceState、4 个 Pinia store、useFormula/useMigration/usePermission 等核心无单测。
- 唯一 runtime 依赖 mathjs 仅用了 `evaluate`（`src/composables/useFormula.ts:5`），全量引入包体积偏大。
- e2e 仅 chromium、且跑在 dev server 上。

## 二、完善方案（按批次执行）

### 批次 B：CI 门禁（价值最高）

新建 `.github/workflows/ci.yml`：

1. job `lint`：`pnpm lint`（去掉 --fix 的校验模式或先 `--fix` 后 `git diff --exit-code`）。
2. job `type-check`：`pnpm type-check`。
3. job `unit`：`pnpm test:unit --run`。
4. job `e2e-p0`：`pnpm playwright test e2e/p0-*.spec.ts`（绕过 pwsh 脚本，见批次 C1）。

Node 20 + pnpm（`cache: pnpm`）。验收：PR 上出现绿色 CI；后续可加 `build:lib` 产物校验 job。

### 批次 C：跨平台与 e2e 强化

1. **C1**：把 `test:e2e:p0/p1/p2/all` 从 pwsh 脚本改为直接调用 playwright（如 `playwright test e2e/p0-engine.spec.ts`），或用 node 重写 `scripts/run-e2e-tests.ts`；保留 ps1 过渡期。CI 与本地共用同一入口。
