# Schema 引擎 (Schemagine) 引用指南

> **版本**: 与 `package.json` 同步（当前 0.2.3） | **包名**: `schemagine` | **类型**: ESM + CJS 双格式库

Schema-driven 动态表单与数据管理引擎。基于 Vue 3 + Pinia + Element Plus + vxe-table 构建，通过 **Schema 配置** 驱动列表、卡片、新增三种视图，无需为每个模块编写重复的 CRUD 代码。

## 1. 安装

### 1.1 安装依赖

```sh
pnpm add schemagine
```

### 1.2 对等依赖

确保项目已安装以下对等依赖（peerDependencies）：

| 包 | 版本要求 | 用途 |
|---|---------|------|
| `vue` | ^3.5 | 框架 |
| `pinia` | ^3.0 | 状态管理（候选值/公式缓存 runtimeCache 在主链路使用） |
| `element-plus` | ^2.13 | UI 组件库 |
| `vue-router` | ^5.0 | 路由（SchemaEditor 可视化编辑器使用） |
| `vxe-table` | ^4.18 | 虚拟滚动表格 |
| `vxe-pc-ui` | ^4.13 | vxe-table UI 配套 |
| `xe-utils` | ^4.0 | vxe-table 工具库 |
| `xlsx` | >=0.18.5（可选） | xlsx 导入/导出；不用电子表格导入导出可不安装 |

```sh
pnpm add vue pinia element-plus vue-router vxe-table vxe-pc-ui xe-utils xlsx
```

> 公式引擎（`mathjs`）是 schemagine 的直接依赖、随包安装，宿主无需单独安装。

### 1.3 额外样式引入

在使用引擎的入口处（如 `main.ts`），需要引入 Element Plus 和 vxe-table 的样式：

```ts
// main.ts
import 'element-plus/dist/index.css'
import 'vxe-pc-ui/lib/style.css'
import 'vxe-table/lib/style.css'

// 引入引擎样式（内含 --sg-* 样式 Token 基线）
import 'schemagine/dist/schemagine.css'
```

### 1.4 主题定制（样式 Token）

引擎全部样式基于 `--sg-*` CSS 变量（token 基线见 `docs/15-样式Token基线.md`，
权威清单在库内 `schemagine.css` 的 `:root` 块）。宿主有三种定制方式，可叠加使用：

```css
/* 1) 零配置：默认跟随 Element Plus 主题（含 html.dark 暗色模式），无需任何代码 */

/* 2) 覆盖 --sg-* token：在任意祖先（如 :root）覆盖，支持只改部分 */
:root {
  --sg-color-primary: #7c3aed;   /* 品牌色，浅色阶/focus 光晕自动跟随 */
  --sg-radius-md: 6px;           /* 全局圆角 */
  --sg-font-size-base: 13px;     /* 基准字号 */
}

/* 3) 覆盖 Element Plus 的 --el-* 变量：引擎基色经 var(--el-*, 回退) 传导，同样生效 */
```

范围说明：颜色（品牌/功能/文字/边框/填充/背景）、字号（8 档）、间距（2px 网格）、
控件高度、圆角（7 档）、阴影（4 档 + focus 光晕）、z-index 层级、过渡时长均已 token 化；
边框宽度、定位偏移、结构宽高保持字面量，不属于主题面。

### 1.5 注册插件

```ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import ElementPlus from 'element-plus'
import VxePcUI from 'vxe-pc-ui'
import VxeTable from 'vxe-table'

const app = createApp(App)
app.use(createPinia())
app.use(ElementPlus)
app.use(VxePcUI)
app.use(VxeTable)
app.mount('#app')
```

### 1.6 ⚠️ Vite 去重配置（必须）

schemagine 通过库模式（Library Mode）构建，它依赖的 `pinia`、`vue`、`vue-router` 被标记为 external（不打包进库产物）。为了避免打包后出现**两份 Symbol 实例**导致 `Cannot read properties of undefined (reading '_s')` 崩溃，消费项目**必须**在 `vite.config.ts` 中配置 `resolve.dedupe`：

```ts
// vite.config.ts
export default defineConfig({
  resolve: {
    dedupe: ['pinia', 'vue', 'vue-router'],
  },
  // ... 其他配置
})
```

> **为什么需要 dedupe？** schemagine 和你的项目各自引用 Pinia 时可能解析到不同的 `node_modules` 副本（如 workspace 共享依赖版本不一时）。Pinia 内部使用 `Symbol('pinia')` 来 provide/inject Store 上下文，两个不同 Symbol 实例无法互相识别，导致 `activePinia` 为 null，Store 调用 `pinia._s` 时报错。

### 1.7 宿主集成边界（解耦契约）

Schemagine 是通用引擎，与任何宿主应用（业务后台）保持**双向零侵入**。以下契约由 CI 守卫 `scripts/check-decoupling.mjs`（`pnpm lint` / `lint:check` 自动执行）强制保障。

**样式边界（引擎 ⇆ 宿主）：**

- 引擎只消费 `--sg-*` token（见 docs/15 样式Token基线），token 基色默认绑定 Element Plus 同名变量，宿主换 EP 主题引擎自动跟随；
- 宿主定制的**唯一入口** = 在任意祖先覆盖 `--sg-*`（`#hex`、字号、间距、圆角均可覆写）；**禁止**用 `:deep()` / 全局选择器穿透引擎内部——`.schema-engine` 根之下的类名不是公共 API，引擎内部结构调整不保证兼容；
- 引擎源码不引用任何宿主类名 / CSS 变量 / SCSS 变量（含注释），违者守卫报错。

**布局边界（引擎自足，宿主零矫正）：**

- 引擎根元素 `.schema-engine` 自带完整布局契约：`height: 100%; min-height: 0; flex column`（撑满父容器且作为可收缩 flex 子项），窄屏（<768px）自动回归文档流自然高度；
- 宿主只需提供：普通容器（引擎撑满）或 flex 容器（引擎与宿主工具条分占空间）+ `overflow: auto` 滚动层；
- 引擎内部 sticky 元素与触底加载自动解析「最近滚动祖先」，滚动容器带 padding-top 亦自适应补偿，宿主无需配合任何类名。

**业务边界（业务逻辑留在宿主）：**

- 引擎不经手业务数据：数据读写经六个 Service 接口由宿主注入（§3），引擎默认只有 mock 实现；
- 业务动作经 `row-action` / `action-trigger` / `batch-patch` 事件上抛宿主执行（§事件），引擎源码零业务模块码、零业务端点；
- 能力扩展走注册表（字段类型 `registerFieldType` / 弹窗 `registerDialog`），引擎不 if-else 具体业务。

## 2. 快速开始

### 2.1 最简集成（4 步）

#### 步骤 1：实现 Service 层

引擎本身不包含业务 API 实现，你需要自己实现以下 6 个 Service 接口（见 §3）：

```ts
// services/MyRecordService.ts
import type { IRecordService, ApiResponse, RecordEntity, RecordListResponse, ListQueryParams, PatchFieldParams, CreateRecordParams, FieldValueCandidateQueryParams, FieldValueCandidateListResponse } from 'schemagine'

export class MyRecordService implements IRecordService {
  async list(params: ListQueryParams): Promise<ApiResponse<RecordListResponse>> {
    const res = await fetch(`/api/modules/${params.moduleId}/records`, {
      method: 'POST',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  /** 表头筛选弹层的候选值（值 + 出现次数）；必选方法 */
  async listFieldValueCandidates(params: FieldValueCandidateQueryParams): Promise<ApiResponse<FieldValueCandidateListResponse>> {
    const res = await fetch(`/api/modules/${params.moduleId}/fields/${params.field}/candidates`, {
      method: 'POST',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  async getDetail(moduleId: string, recordId: string): Promise<ApiResponse<RecordEntity>> {
    const res = await fetch(`/api/modules/${moduleId}/records/${recordId}`)
    return res.json()
  }

  async patchField(params: PatchFieldParams): Promise<ApiResponse<RecordEntity>> {
    const res = await fetch(`/api/modules/${params.moduleId}/records/${params.recordId}`, {
      method: 'PATCH',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  async create(params: CreateRecordParams): Promise<ApiResponse<RecordEntity>> {
    const res = await fetch(`/api/modules/${params.moduleId}/records`, {
      method: 'POST',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  async batchCreate(params: CreateRecordParams[]): Promise<ApiResponse<RecordEntity[]>> {
    const res = await fetch(`/api/modules/${params[0].moduleId}/records/batch`, {
      method: 'POST',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  // 可选：实时数据订阅（docs/19 I1）。不实现则实时特性关闭，其余功能不受影响。
  // subscribeRecords?(moduleId, cb) { ... } —— 契约见 §3.10
}
```

#### 步骤 2：在应用入口注入 Service

```ts
// main.ts
import { setRecordService, setSchemaService, setCandidateService, setUserViewConfigService, setRelationService } from 'schemagine'
import { MyRecordService } from './services/MyRecordService'
import { MySchemaService } from './services/MySchemaService'
import { MyCandidateService } from './services/MyCandidateService'
import { MyUserViewConfigService } from './services/MyUserViewConfigService'
import { MyRelationService } from './services/MyRelationService'

setRecordService(new MyRecordService())
setSchemaService(new MySchemaService())
setCandidateService(new MyCandidateService())
setUserViewConfigService(new MyUserViewConfigService())
setRelationService(new MyRelationService())
```

#### 步骤 3：在页面中使用

```vue
<script setup lang="ts">
import { SchemaEngine } from 'schemagine'

const moduleId = 'my-module-id'

function handleModuleLoaded(payload: { moduleId: string }) {
  console.log('模块加载完成:', payload.moduleId)
}

function handleDataChanged(payload: { moduleId: string }) {
  console.log('数据已变更:', payload.moduleId)
}
</script>

<template>
  <SchemaEngine
    :module-id="moduleId"
    @module-loaded="handleModuleLoaded"
    @data-changed="handleDataChanged"
  />
</template>
```

#### 步骤 4：运行

```sh
pnpm dev
```

## 3. Service 注入模式（核心集成点）

引擎采用 **依赖注入（Service Injection）** 模式：引擎本身不耦合业务 API，业务方提供 Service 实现后注入。这是集成的核心。

### 3.1 6 个 Service 接口

| 接口 | 注入函数 | 职责 |
|------|---------|------|
| `IRecordService` | `setRecordService()` | 记录 CRUD + 字段候选值（+ 可选实时订阅） |
| `ISchemaService` | `setSchemaService()` | Schema / 权限加载 |
| `ICandidateService` | `setCandidateService()` | FK 下拉候选值查询 |
| `IUserViewConfigService` | `setUserViewConfigService()` | 用户视图配置（列宽/列序/显隐/卡片布局/筛选预设） |
| `IRelationService` | `setRelationService()` | 关联关系（一对多/多对多/反向引用） |
| `IMediaService` | `setMediaService()` | 媒体库（`mediaImage` 字段的列表/上传/URL 解析） |

> 未注入 `IMediaService` 时 `mediaImage` 字段无法解析图片 URL（显示占位），其余功能不受影响。

### 3.2 IRecordService 接口详情

```ts
interface IRecordService {
  list(params: ListQueryParams): Promise<ApiResponse<RecordListResponse>>
  /** 表头筛选弹层的字段值候选（值 + 出现次数），必选方法 */
  listFieldValueCandidates(params: FieldValueCandidateQueryParams): Promise<ApiResponse<FieldValueCandidateListResponse>>
  getDetail(moduleId: string, recordId: string): Promise<ApiResponse<RecordEntity>>
  patchField(params: PatchFieldParams): Promise<ApiResponse<RecordEntity>>
  create(params: CreateRecordParams): Promise<ApiResponse<RecordEntity>>
  batchCreate(params: CreateRecordParams[]): Promise<ApiResponse<RecordEntity[]>>
  /** 可选：实时订阅（契约见 §3.10）；不实现则引擎不订阅 */
  subscribeRecords?(moduleId: string, cb: (change: RecordsChangePayload) => void): () => void
}

interface ListQueryParams {
  moduleId: string
  /** 过滤条件：顶层隐式 AND；组合逻辑（OR/嵌套）用 FilterGroup 表达（见 §5.5） */
  filters?: FilterCondition[]
  /** 关键词跨字段搜索（按模块 searchFields 跨字段 OR 包含匹配）；不支持方可忽略 */
  keyword?: string
  sort?: SortParam
  page: number
  pageSize: number
  viewMode?: 'list' | 'card'
}

interface FieldValueCandidateQueryParams {
  moduleId: string
  field: string
  keyword?: string
  page: number
  pageSize: number
  filters?: FilterCondition[]
}

interface PatchFieldParams {
  moduleId: string
  recordId: string
  field: string
  value: unknown
  expectedVersion: number  // 乐观锁版本号：与记录当前 version 不符时返回 VERSION_CONFLICT
  force?: boolean
}
```

### 3.3 ISchemaService 接口详情

```ts
interface ISchemaService {
  loadModuleSchema(moduleId: string): Promise<ApiResponse<ModuleSchema>>
  loadModulePermissions(moduleId: string): Promise<ApiResponse<ModulePermissions>>
  validateSchema(moduleId: string): Promise<ApiResponse<boolean>>
  saveModuleSchema(schema: ModuleSchema): Promise<ApiResponse<void>>
  listModuleIds(): Promise<ApiResponse<string[]>>
}
```

### 3.4 Service 未初始化时的行为

如果未注入 Service，引擎会返回 Fallback 实现（所有方法返回错误响应 `SERVICE_NOT_INITIALIZED`），并在控制台打印错误日志。**引擎不会崩溃**，但功能不可用。

### 3.5 响应格式

```ts
interface ApiResponse<T> {
  success: boolean
  data: T
  message?: string
  errorCode?: string   // 见 §3.11 错误码
  details?: unknown[]
}
```

### 3.6 ICandidateService 接口详情

FK 字段下拉候选值查询（与 §3.2 的 `listFieldValueCandidates` 区分：这个是**按目标模块**查可选项，那个是**按当前模块字段**查已有值分布）。

```ts
interface ICandidateService {
  query(params: CandidateQueryParams): Promise<ApiResponse<CandidateListResponse>>
}

interface CandidateQueryParams {
  targetModule: string        // FK 目标模块
  keyword?: string
  page: number
  pageSize: number
  filters?: Record<string, unknown>
}

interface CandidateListResponse {
  options: CandidateOption[]  // { value, label, disabled? }
  total: number
  hasMore: boolean
}
```

### 3.7 IUserViewConfigService 接口详情

用户视图配置的持久化通道：列设置（显隐/宽度/固定/列序）、卡片布局、筛选预设、pageSize、defaultSort 都经由它落库。**语义为按模块整体读写**（引擎读改写后整体 save，宿主无需做合并）。

```ts
interface IUserViewConfigService {
  load(moduleId: string): Promise<ApiResponse<UserViewConfig>>
  save(config: UserViewConfig): Promise<ApiResponse<void>>
}

interface UserViewConfig {
  moduleId: string
  version: number
  columns: ColumnConfig[]      // { field, width?, visible, fixed?, order, sortable }
  defaultSort?: SortParam
  pageSize: number
  filterPresets?: FilterPreset[]   // { id, name, filters, sort?, isDefault? }
  viewMode?: 'list' | 'card'
  cardLayout?: CardLayoutConfig
}
```

`load` 返回失败或无数据时引擎回退默认配置（`createDefaultConfig`），不阻断模块加载。

### 3.8 IRelationService 接口详情

关联关系读写（`one-to-many` / `many-to-many` / `reverse-ref` 字段的关系弹层与子表都走这里）。三个读方法均为异步签名。

```ts
interface IRelationService {
  /** 正向：sourceRecord.fieldKey 关联的条目 */
  getRelations(sourceModuleId: string, sourceRecordId: string, fieldKey: string): Promise<ApiResponse<RelationEntry[]>>
  /** 反向：作为 target 被哪些 source 关联 */
  getTargetRelations(targetModuleId: string, targetRecordId: string, fieldKey: string): Promise<ApiResponse<RelationEntry[]>>
  /** 反向视图取源记录实体 */
  getSourceRecords(targetModuleId: string, targetRecordId: string, fieldKey: string): Promise<ApiResponse<RecordEntity[]>>
  addRelation(entry: Omit<RelationEntry, 'id' | 'createdAt' | 'updatedAt'>): Promise<ApiResponse<RelationEntry>>
  /** 只更新连带字段（extraFields） */
  updateRelation(id: string, extraFields: Record<string, unknown>): Promise<ApiResponse<RelationEntry>>
  removeRelation(id: string): Promise<ApiResponse<void>>
}
```

### 3.9 IMediaService 接口详情

媒体通道（`mediaImage` 字段与媒体库组件的数据面）：列表选择、上传、把媒体 id 解析为可访问 URL。未注入时 `mediaImage` 字段按「url 模式」降级（值即 URL 原样渲染），不影响其他功能。

```ts
interface IMediaService {
  list(params: MediaListParams): Promise<ApiResponse<MediaListResponse>>
  upload(file: File): Promise<ApiResponse<MediaAsset>>
  /** 媒体 id → URL 的批量解析（引擎带缓存，clearMediaUrlCache() 可清） */
  resolveUrls(ids: string[]): Promise<ApiResponse<Record<string, string>>>
  /** 可选：删除媒体记录（提供后 MediaLibrary 管理页才出删除按钮） */
  remove?(id: string): Promise<ApiResponse<null>>
  /** 可选：手动登记外部 URL 资源（提供后 MediaLibrary 才出「新建资源」） */
  createManual?(fields: { file_name: string; url: string; kind?: string }): Promise<ApiResponse<MediaAsset>>
}
```

不想手写胶水的宿主可直接用 `schemagine/media` 的 [`createHttpMediaService()`](#_3-13-媒体管理四种接入模式schemaginemedia-可选导出) 按约定对接后端四类接口，零胶水获得完整实现。

### 3.10 实时数据订阅契约（可选）

宿主在 `IRecordService.subscribeRecords` 中提供传输实现（轮询 / SSE / WebSocket 均可），引擎负责增量合并：

```ts
// 宿主实现示例（SSE）
subscribeRecords(moduleId: string, cb: (change: RecordsChangePayload) => void) {
  const es = new EventSource(`/api/modules/${moduleId}/events`)
  es.onmessage = (e) => cb(JSON.parse(e.data))
  return () => es.close()   // 返回退订函数，引擎在卸载/换模块时调用
}
```

```ts
interface RecordsChangePayload {
  moduleId: string
  /** 变更行的完整记录：按 id upsert——存在则整体替换 fields/version/updatedAt，不存在则追加（total +1） */
  upserts?: RecordEntity[]
  /** 被删除的记录 id（total -1） */
  deletes?: string[]
}
```

**合并语义（引擎侧，已定稿 docs/19 §六）：**

- 非编辑行：**静默合并**——upsert 整体替换、delete 按行移除，不弹任何提示；
- 正在行内编辑的行：**跳过合并并提示冲突**（编辑会话基于旧数据引用，合并会掀掉编辑中的数据），编辑结束后由宿主的下一次推送自然补齐；
- 保存链路仍走 `expectedVersion` 乐观锁兜底；宿主如需「远端变更强提示」，在传输层自行拦截即可，引擎不重复弹窗。

### 3.11 错误码

| errorCode | 场景 |
|-----------|------|
| `VERSION_CONFLICT` | 乐观锁冲突（expectedVersion 与服务端不一致） |
| `PERMISSION_DENIED` | 权限不足 |
| `VALIDATION_FAILED` | 服务端校验失败 |
| `NOT_FOUND` | 记录/模块不存在 |
| `SERVICE_NOT_INITIALIZED` | Service 未注入（Fallback 返回，见 §3.4） |

### 3.12 本地数据源（喂数组即跑）

原型、演示或纯前端场景不想实现后端契约时，`createLocalRecordService` 把一个数组变成完整的 `IRecordService`（内存分页/排序/组合过滤/候选值/CRUD，与 Mock 同一套求值口径）：

```ts
import { createLocalRecordService, setRecordService } from 'schemagine'

setRecordService(createLocalRecordService({

```

### 3.13 媒体管理：四种接入模式（`schemagine/media` 可选导出）

图片类字段（`image` / `mediaImage`）的接入深度由宿主按需选择，四种模式共用同一套字段与编辑面，可平滑升级、互不锁死：

| 模式 | 适用场景 | 字段值形态 | 需要做的 |
|------|---------|-----------|---------|
| ① url（默认） | 只用表格组件，图片已有外链 | URL 字符串 | 什么都不做，直接渲染 |
| ② oss 直传 | 前端直传对象存储（S3 兼容 / 七牛） | 最终 URL | `setupMedia({ mode: 'oss', oss })` |
| ③ api 上传 | 宿主后端提供上传接口 | 最终 URL | `setupMedia({ mode: 'api', api })` |
| ④ media library | 宿主后端实现媒体库契约 | 媒体 id | `setMediaService(impl)` + 媒体库组件 |

编辑面随模式自动降级：① 只有 URL 手填；②③ URL 手填 + 上传按钮；④ 媒体库选择 + 上传。模式在引擎挂载前通过 `setupMedia()` 声明一次即可，表格行内编辑、表单编辑器、媒体选择与媒体库组件全部随之适配。

**模式①（默认）**：不引入 `schemagine/media`、不调任何函数。`image` / `mediaImage` 字段值是 URL 就直接渲染 `<img>`，编辑时手填地址。

**模式②（oss 直传）**：纯前端直传，签名在本地计算（零 SDK 依赖）：

```ts
import { setupMedia } from 'schemagine/media'

// 七牛：本地生成上传凭证（HMAC-SHA1），支持 z0/z1/z2/na0/as0/cn-east-2 或 uploadUrl 覆盖
setupMedia({
  mode: 'oss',
  oss: {
    provider: 'qiniu',
    accessKey: 'ak', secretKey: 'sk', bucket: 'my-bucket',
    domain: 'https://cdn.example.com',   // 外链域名，最终 URL = domain + '/' + key
    zone: 'z0',                           // 或 uploadUrl: 'https://自建网关/upload'
    keyPrefix: 'images/',
  },
})

// S3 兼容（AWS / MinIO / 各云 S3 端点）：SigV4 纯 JS 签名，UNSIGNED-PAYLOAD 免整文件哈希
setupMedia({
  mode: 'oss',
  oss: {
    provider: 's3',
    bucket: 'my-bucket', region: 'us-east-1',
    accessKeyId: 'ak', secretAccessKey: 'sk',   // STS 场景另传 sessionToken
    // endpoint: 'http://minio.internal:9000', addressStyle: 'path',  // MinIO 常用
    // publicUrlBase: 'https://cdn.example.com',                      // CDN 域名
    keyPrefix: 'images/',
  },
})
```

> 安全提示：AK/SK 暴露在前端仅适合内网后台或权限受限的临时凭证；公网产品请用模式③让后端签名/代理。

**模式③（api 上传）**：宿主后端实现一个上传接口，按约定返回图片 URL：

```ts
setupMedia({
  mode: 'api',
  api: {
    endpoint: '/api/v1/upload',        // POST multipart，文件字段名默认 'file'
    headers: { authorization: 'Bearer …' },
    extraFields: { biz: 'invoice' },   // 附加表单字段（静态或按文件函数）
    // parseResponse?: (body) => url   // 整体接管解析；默认约定见下
  },
})
```

响应约定：JSON 的 `url` → `data.url` → `data.data.url`（兼容 `{code:0,data:{url}}` 信封），纯文本形如 URL 也接受，相对路径按当前站点补全。

**模式④（media library）**：宿主按 §3.9 契约实现 `IMediaService` 并注入，同时同步引入媒体库组件。懒人路径——`createHttpMediaService()` 按约定对接后端即得完整实现：

```ts
import { setMediaService } from 'schemagine'
import { createHttpMediaService, MediaLibrary, MediaPickerDialog } from 'schemagine/media'

setMediaService(createHttpMediaService({
  baseUrl: '/api/v1',
  // 默认路径：GET /media/list、POST /media/upload、POST /media/lookup
  removePath: '/records/media',        // 提供 → DELETE {base}{removePath}/{id}，管理页出删除按钮
  createManualPath: '/records/media',  // 提供 → POST {base}{createManualPath}，出「新建资源」
  headers: () => ({ authorization: `Bearer ${token()}` }),
  // unwrap: (body) => body.data,      // 宿主有 {code,data} 信封时在此剥离
}))
```

媒体库组件集（均在 `schemagine/media` 子路径）：

| 组件 | 用途 |
|------|------|
| `MediaLibrary` | 媒体库管理页：上传（多选）/类型与关键字筛选/分页/复制 ID·URL/删除/手动登记；`remove`、`createManual` 未提供时对应入口自动隐藏；`defineExpose({ refresh, uploadFiles })` |
| `MediaPickerDialog` | 媒体选择弹窗：单选（`select` 事件，引擎编辑内建）；`multiple` 多选（`selectMany` 事件，宿主自建多图场景） |
| `MediaImageCell` / `MediaImageEditor` | 单元格缩略图与表单编辑器（引擎已内建使用，亦可独立取用） |
| `uploadToS3` / `uploadToQiniu` / `uploadViaApi` | 底层直传函数，可脱离引擎独立使用 |

**说明与约束**：

- `schemagine/media` 是可选子路径导出，`import { … } from 'schemagine/media'`；不需要媒体能力的宿主只引主入口，零额外体积。样式沿用主包 `schemagine.css`（`--sg-*` token）。
- `list` 仅在模式④有意义；②③模式下引擎内建的媒体库选择入口自动隐藏（直传无清单可列）。
- 值兼容：字段值命中 `media-xxxxxxxx`（8 位十六进制）形态才走媒体解析，存量 URL 记录原样渲染，四种模式可对同一张表混用与渐进迁移。
- 引擎内建的 `MediaServiceInvoker` 代理对 `remove` / `createManual` 做了未实现兜底，媒体库组件调用前无需判空。

| `runSchemaMigrations(schema, records)` | 运行 Schema 迁移脚本 |
| `useMounted()` | 竞态安全挂载检测 |

## 8. 扩展与进阶

### 8.1 自定义字段类型（registerFieldType）

内置 24 种字段类型不可覆盖；新类型经 `registerFieldType` 注册后在渲染、表单、行内编辑三处自动生效：

```ts
import { registerFieldType } from 'schemagine'
import ProgressEditor from './ProgressEditor.vue'   // 约定 props { modelValue?, fieldSchema, disabled?, readonly? }，emit update:model-value

registerFieldType('progress', {
  // 展示渲染器：输出单元格/卡片 HTML；缺省按 text 渲染
  renderToHtml: (ctx) => `<div class="my-progress" style="width:${ctx.value ?? 0}%"></div>`,
  // 编辑器组件：表单与行内编辑共用
  editor: ProgressEditor,
  // 值适配（可选）：记录值 ⇄ 编辑器回显值，缺省原样透传
  toEditorValue: (v) => Number(v) || 0,
  toRecordValue: (v) => v,
})
```

注册后 Schema 里即可声明 `{ type: 'progress', ... }` 字段。相关 API：`unregisterFieldType` / `isRegisteredFieldType` / `isBuiltinFieldType`。

### 8.2 自定义弹窗（registerDialog）

`openDialog` 的类型系统是开放的（`ExtendedDialogType` = 内置 7 种 + 自定义 string）。注册后 schema 动作或引擎流程即可触发宿主注册的弹窗组件：

```ts
import { registerDialog } from 'schemagine'
import MyApprovalDialog from './MyApprovalDialog.vue'

registerDialog('approval', MyApprovalDialog)
```

### 8.3 外观契约（EngineAppearance）

`appearance` prop 控制全局观感，速览如下（权威文档 [docs/20-外观与格式契约.md](./20-外观与格式契约.md)）：

| 键 | 取值 | 说明 |
|----|------|------|
| `tableBorder` | `'full' \| 'inner' \| 'outer' \| 'none'` | 表格边框（默认 `'inner'`） |
| `valueDisplay` | `'tag' \| 'plain' \| 'classic'` | 单元格值展示：彩色标签（默认）/ 纯文本 / 严格单色电子表格风 |
| `cardDensity` | `'default' \| 'compact'` | 卡片（详情/编辑）密度：每行 2 个（默认）/ 每行 4 个 |
| `inlineEditLayout` | `'float' \| 'fit-row'` | 行内编辑布局：浮层（默认）/ 行内收纳（适配宿主严格裁剪环境） |
| `exportCsvInConservative` | `boolean` | 保守工具栏下保留「导出CSV」（默认 false，仍受 permissions.export 管控） |
| `exportExcelInConservative` | `boolean` | 保守工具栏下保留「导出Excel」（同上） |

字段级可用 `FieldSchema.displayStyle` 在全局 plain 下保留关键列彩色。

### 8.4 i18n（多语言）

引擎内置 zh-CN 基准语言包（零依赖、无异步加载）。宿主经 `registerLocale` 注入同结构语言包后，用 `locale` prop 切换：

```ts
import { registerLocale } from 'schemagine'
import enUS from './locales/en-US.json'   // 结构参照 schemagine 内置 zh-CN 包（点路径 key + {name} 插值）

registerLocale('en-US', enUS)
```

```vue
<SchemaEngine :module-id="id" locale="en-US" />
```

- 未注册的语言回退 zh-CN 并在控制台告警；
- 也可编程切换：`setLocale('en-US')`（`getLocale()` 读取当前值）；
- 自定义弹层想复用同源文案可直接调 `t('table.editAction')`；
- 语言包结构参照 `src/locales/zh-CN.ts`（同 key 覆盖基准包）。

### 8.5 声明式规则（rules 包）

schema 的 `ModuleSchema.rules` / `FieldSchema.rules`（八类：condition/compute/map/lookup/validate/action/style/aggregate）经 `schemagine/rules` 子路径包的 `RulesRuntime` 求值，引擎已接线三个执行语义：

1. **compute 写回**：行内编辑提交后，`watch` 命中编辑字段的 compute 规则按声明序求值并级联（引用前序 target 的规则同轮连锁），结果写回行数据；派生字段经同一 `cell-edit` 链持久化（值未变化自动去重）。
2. **validate 拦截**：`when` 为**违反条件**（true 即违规），无 `force` 时拦截提交并提示 `message`；带 `force` 时改写为强制值放行。与既有 `rowValidationRules` 并存，先后各自求值。
3. **动作执行**：`RowActionConfig.action`（ActionAct 槽位）声明后，点击产出 Effect 描述符（confirm → invoke/open/navigate → toast，`{{expr}}` 插值）交宿主 `rulesExecutor` prop 执行——**action 与 target 二选一，同时声明 action 优先，同一动作禁双挂**：

```vue
<SchemaEngine
  :module-id="id"
  :rules-executor="(effects, ctx) => hostRunEffects(effects, ctx)"
/>
```

4. **派生位**：`rowAction.labelWhen: [{ when, label }]` 按行切换按钮文案（操作列计价取最长候选文案）；aggregate 规则 `{ key, expr }` 追加为列表统计条末尾项（列值数组入作用域，如 `sum(amount)`）。

规则结构校验已接入 `validateSchema`（非法规则以 error 级诊断定位到 `fields[i].rules[...]`）；独立校验器 `validateRules / validateFlow / validateDictionary` 可在宿主服务端复用。规则与 `visibleWhen/formulaConfig/aggregation` 等既有位并存：规则优先、未覆盖处既有位继续生效。


### 9.2 数据流

```
UI 操作 → Composable（逻辑层）→ Service（API 层）→ 后端
                ↓
        状态更新（响应式）
                ↓
        视图自动刷新
```

### 9.3 关键设计决策

| 决策 | 说明 |
|------|------|
| **Service Injection** | 引擎不耦合业务 API，通过接口注入实现 |
| **Schema-Driven** | 所有视图由 Schema 配置驱动，无需手写模板 |
| **乐观锁** | 写操作携带 `version`，冲突时自动重试 |
| **多实例隔离** | `create*State()` 工厂函数确保每个实例独立 |
| **ErrorBoundary** | 渲染异常不扩散，仅影响当个实例 |
| **服务降级** | Service 未初始化时返回 Fallback 而非崩溃 |

## 11. FAQ / 常见问题

### Q1：引擎会与宿主应用的状态冲突吗？

不会。引擎主链路状态以 `createSchemaMetaState()` / `createRecordState()` / `createUiState()` 工厂创建实例并经 Vue `provide/inject` 隔离（Pinia 仅承载候选值/公式缓存，挂宿主的 Pinia 实例），多个 `SchemaEngine` 实例之间互不干扰。

### Q2：如何替换默认的 UI 组件？

引擎的所有 UI 基于 Element Plus + vxe-table。你可以在自己的项目中：
- 覆盖 Element Plus 主题变量（CSS Variables）
- 使用 `FieldEditorFactory` + `ValueRenderer` 搭配自己的组件
- 完全替换视图层（使用 `useSchemaMeta()` / `useRecords()` 消费状态）

### Q3：如何处理权限？

权限分两层：
1. **模块级权限**（`ModulePermissions`）：由 `ISchemaService.loadModulePermissions()` 返回
2. **字段级权限**（`FieldPermission`）：定义在 `FieldSchema.permission` 中

引擎自动根据权限控制 UI 的显示/编辑状态。你还可以通过 `usePermission()` composable 在自定义组件中检查权限。

### Q4：表格大数据量性能如何？

表格基于 `vxe-table`，支持：
- 虚拟滚动（万级数据流畅）
- 列拖拽排序
- 列固定
- 自定义列宽

### Q5：Schema 变更后旧数据怎么办？

使用 Schema 迁移机制：
1. 在 `ModuleSchema.migrations[]` 中定义迁移脚本（`fromVersion` → `toVersion`）
2. 引擎在加载数据时自动执行迁移
3. 字段重命名使用 `FieldSchema.previousKeys[]`，旧 key 数据自动映射到新 key

### Q6：构建产物包含哪些内容？

```
dist/
├── schemagine.mjs        # ESM 格式（适用于现代打包器）
├── schemagine.cjs        # CJS 格式（适用于 Node.js require）
├── schemagine.css        # 引擎样式
├── index.d.ts            # 类型定义入口
└── ...                    # 各模块 .d.ts 文件
```
