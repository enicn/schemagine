# Schema 引擎 (Schemagine) 引用指南

> **版本**: 0.1.0 | **包名**: `schemagine` | **类型**: ESM + CJS 双格式库

Schema-driven 动态表单与数据管理引擎。基于 Vue 3 + Pinia + Element Plus + vxe-table 构建，通过 **Schema 配置** 驱动列表、卡片、新增三种视图，无需为每个模块编写重复的 CRUD 代码。

## 1. 安装

### 1.1 安装依赖

```sh
pnpm add schemagine
```

### 1.2 对等依赖

确保项目已安装以下对等依赖（peerDependencies）：

| 包 | 版本要求 | 用途 |
|---|---------|------|
| `vue` | ^3.5 | 框架 |
| `pinia` | ^3.0 | 状态管理 |
| `element-plus` | ^2.13 | UI 组件库 |
| `vue-router` | ^5.0 | 路由 |
| `vxe-table` | ^4.18 | 虚拟滚动表格 |
| `vxe-pc-ui` | ^4.13 | vxe-table UI 配套 |
| `xe-utils` | ^4.0 | vxe-table 工具库 |
| `mathjs` | ^15 | 公式引擎 |

```sh
pnpm add vue pinia element-plus vue-router vxe-table vxe-pc-ui xe-utils mathjs
```

### 1.3 额外样式引入

在使用引擎的入口处（如 `main.ts`），需要引入 Element Plus 和 vxe-table 的样式：

```ts
// main.ts
import 'element-plus/dist/index.css'
import 'vxe-pc-ui/lib/style.css'
import 'vxe-table/lib/style.css'

// 引入引擎样式（内含 --sg-* 样式 Token 基线）
import 'schemagine/dist/style.css'
```

### 1.4 主题定制（样式 Token）

引擎全部样式基于 `--sg-*` CSS 变量（token 基线见 `docs/15-样式Token基线.md`，
权威清单在库内 `schemagine.css` 的 `:root` 块）。宿主有三种定制方式，可叠加使用：

```css
/* 1) 零配置：默认跟随 Element Plus 主题（含 html.dark 暗色模式），无需任何代码 */

/* 2) 覆盖 --sg-* token：在任意祖先（如 :root）覆盖，支持只改部分 */
:root {
  --sg-color-primary: #7c3aed;   /* 品牌色，浅色阶/focus 光晕自动跟随 */
  --sg-radius-md: 6px;           /* 全局圆角 */
  --sg-font-size-base: 13px;     /* 基准字号 */
}

/* 3) 覆盖 Element Plus 的 --el-* 变量：引擎基色经 var(--el-*, 回退) 传导，同样生效 */
```

范围说明：颜色（品牌/功能/文字/边框/填充/背景）、字号（8 档）、间距（2px 网格）、
控件高度、圆角（7 档）、阴影（4 档 + focus 光晕）、z-index 层级、过渡时长均已 token 化；
边框宽度、定位偏移、结构宽高保持字面量，不属于主题面。

### 1.5 注册插件

```ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import ElementPlus from 'element-plus'
import VxePcUI from 'vxe-pc-ui'
import VxeTable from 'vxe-table'

const app = createApp(App)
app.use(createPinia())
app.use(ElementPlus)
app.use(VxePcUI)
app.use(VxeTable)
app.mount('#app')
```

### 1.6 ⚠️ Vite 去重配置（必须）

schemagine 通过库模式（Library Mode）构建，它依赖的 `pinia`、`vue`、`vue-router` 被标记为 external（不打包进库产物）。为了避免打包后出现**两份 Symbol 实例**导致 `Cannot read properties of undefined (reading '_s')` 崩溃，消费项目**必须**在 `vite.config.ts` 中配置 `resolve.dedupe`：

```ts
// vite.config.ts
export default defineConfig({
  resolve: {
    dedupe: ['pinia', 'vue', 'vue-router'],
  },
  // ... 其他配置
})
```

> **为什么需要 dedupe？** schemagine 和你的项目各自引用 Pinia 时可能解析到不同的 `node_modules` 副本（如 workspace 共享依赖版本不一时）。Pinia 内部使用 `Symbol('pinia')` 来 provide/inject Store 上下文，两个不同 Symbol 实例无法互相识别，导致 `activePinia` 为 null，Store 调用 `pinia._s` 时报错。

## 2. 快速开始

### 2.1 最简集成（4 步）

#### 步骤 1：实现 Service 层

引擎本身不包含业务 API 实现，你需要自己实现以下 5 个 Service 接口：

```ts
// services/MyRecordService.ts
import type { IRecordService, ApiResponse, RecordEntity, RecordListResponse, ListQueryParams, PatchFieldParams, CreateRecordParams } from 'schemagine'

export class MyRecordService implements IRecordService {
  async list(params: ListQueryParams): Promise<ApiResponse<RecordListResponse>> {
    const res = await fetch(`/api/modules/${params.moduleId}/records`, {
      method: 'POST',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  async getDetail(moduleId: string, recordId: string): Promise<ApiResponse<RecordEntity>> {
    const res = await fetch(`/api/modules/${moduleId}/records/${recordId}`)
    return res.json()
  }

  async patchField(params: PatchFieldParams): Promise<ApiResponse<RecordEntity>> {
    const res = await fetch(`/api/modules/${params.moduleId}/records/${params.recordId}`, {
      method: 'PATCH',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  async create(params: CreateRecordParams): Promise<ApiResponse<RecordEntity>> {
    const res = await fetch(`/api/modules/${params.moduleId}/records`, {
      method: 'POST',
      body: JSON.stringify(params),
    })
    return res.json()
  }

  async batchCreate(params: CreateRecordParams[]): Promise<ApiResponse<RecordEntity[]>> {
    const res = await fetch(`/api/modules/${params[0].moduleId}/records/batch`, {
      method: 'POST',
      body: JSON.stringify(params),
    })
    return res.json()
  }
}
```

#### 步骤 2：在应用入口注入 Service

```ts
// main.ts
import { setRecordService, setSchemaService, setCandidateService, setUserViewConfigService, setRelationService } from 'schemagine'
import { MyRecordService } from './services/MyRecordService'
import { MySchemaService } from './services/MySchemaService'
import { MyCandidateService } from './services/MyCandidateService'
import { MyUserViewConfigService } from './services/MyUserViewConfigService'
import { MyRelationService } from './services/MyRelationService'

setRecordService(new MyRecordService())
setSchemaService(new MySchemaService())
setCandidateService(new MyCandidateService())
setUserViewConfigService(new MyUserViewConfigService())
setRelationService(new MyRelationService())
```

#### 步骤 3：在页面中使用

```vue
<script setup lang="ts">
import { SchemaEngine } from 'schemagine'

const moduleId = 'my-module-id'

function handleModuleLoaded(payload: { moduleId: string }) {
  console.log('模块加载完成:', payload.moduleId)
}

function handleDataChanged(payload: { moduleId: string }) {
  console.log('数据已变更:', payload.moduleId)
}
</script>

<template>
  <SchemaEngine
    :module-id="moduleId"
    @module-loaded="handleModuleLoaded"
    @data-changed="handleDataChanged"
  />
</template>
```

#### 步骤 4：运行

```sh
pnpm dev
```

## 3. Service 注入模式（核心集成点）

引擎采用 **依赖注入（Service Injection）** 模式：引擎本身不耦合业务 API，业务方提供 Service 实现后注入。这是集成的核心。

### 3.1 5 个 Service 接口

| 接口 | 注入函数 | 职责 |
|------|---------|------|
| `IRecordService` | `setRecordService()` | 记录 CRUD |
| `ISchemaService` | `setSchemaService()` | Schema / 权限加载 |
| `ICandidateService` | `setCandidateService()` | 候选值查询（FK 下拉） |
| `IUserViewConfigService` | `setUserViewConfigService()` | 用户视图配置（列宽/排序/卡片布局） |
| `IRelationService` | `setRelationService()` | 关联关系（一对多/多对多） |

### 3.2 IRecordService 接口详情

```ts
interface IRecordService {
  list(params: ListQueryParams): Promise<ApiResponse<RecordListResponse>>
  getDetail(moduleId: string, recordId: string): Promise<ApiResponse<RecordEntity>>
  patchField(params: PatchFieldParams): Promise<ApiResponse<RecordEntity>>
  create(params: CreateRecordParams): Promise<ApiResponse<RecordEntity>>
  batchCreate(params: CreateRecordParams[]): Promise<ApiResponse<RecordEntity[]>>
}

interface ListQueryParams {
  moduleId: string
  filters?: FilterClause[]
  sort?: SortParam
  page: number
  pageSize: number
  cursor?: string
  viewMode?: 'list' | 'card'
}

interface PatchFieldParams {
  moduleId: string
  recordId: string
  field: string
  value: unknown
  expectedVersion: number  // 乐观锁版本号
  force?: boolean
}
```

### 3.3 ISchemaService 接口详情

```ts
interface ISchemaService {
  loadModuleSchema(moduleId: string): Promise<ApiResponse<ModuleSchema>>
  loadModulePermissions(moduleId: string): Promise<ApiResponse<ModulePermissions>>
  validateSchema(moduleId: string): Promise<ApiResponse<boolean>>
  saveModuleSchema(schema: ModuleSchema): Promise<ApiResponse<void>>
  listModuleIds(): Promise<ApiResponse<string[]>>
}
```

### 3.4 Service 未初始化时的行为

如果未注入 Service，引擎会返回 Fallback 实现（所有方法返回错误响应 `SERVICE_NOT_INITIALIZED`），并在控制台打印错误日志。**引擎不会崩溃**，但功能不可用。

### 3.5 响应格式

```ts
interface ApiResponse<T> {
  success: boolean
  data: T
  message?: string
  errorCode?: string
  details?: unknown[]
}
```

## 4. 组件 API 参考

### 4.1 SchemaEngine（主入口）

```vue
<SchemaEngine
  :module-id="string"
  :initial-view-mode="'list' | 'card' | 'create'"
  :embedded="boolean"
  :readonly="boolean"
  @module-loaded="{ moduleId: string }"
  @view-mode-change="{ mode: 'list' | 'card' | 'create' }"
  @data-changed="{ moduleId: string }"
  @error="{ moduleId: string; code: string; message: string }"
  @request-open-dialog="{ dialogType: string; payload: Record<string, unknown> }"
/>
```

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `moduleId` | `string` | 必填 | 模块 ID，用于加载对应的 Schema 和数据 |
| `initialViewMode` | `'list' \| 'card' \| 'create'` | Schema 默认值 | 初始视图模式 |
| `embedded` | `boolean` | `false` | 嵌入模式（移除边距和背景） |
| `readonly` | `boolean` | `false` | 全局只读模式 |

| 事件 | 载荷 | 触发时机 |
|------|------|---------|
| `module-loaded` | `{ moduleId }` | Schema 加载完成 |
| `view-mode-change` | `{ mode }` | 视图切换 |
| `data-changed` | `{ moduleId }` | 数据变更 |
| `error` | `{ moduleId, code, message }` | 加载/运行时错误 |
| `request-open-dialog` | `{ dialogType, payload }` | 请求打开弹窗 |

**暴露的方法（通过 `ref` 访问）：**

```ts
const engineRef = ref<InstanceType<typeof SchemaEngine>>()

engineRef.value?.refresh()          // 重新加载模块
engineRef.value?.setViewMode('card') // 切换视图
engineRef.value?.getCurrentRecord()  // 获取当前记录
```

| 组件 | 路径 | 说明 |

## 5. TypeScript 类型参考

### 5.1 ModuleSchema（模块 Schema 定义）

```ts
interface ModuleSchema {
  id: string                        // 模块 ID
  name: string                      // 模块名称
  version: string                   // 语义化版本号
  moduleType: 'list' | 'card' | 'both'
  fields: FieldSchema[]             // 字段定义列表
  permissions: ModulePermissions    // 模块级权限
  defaultViewMode: 'list' | 'card' | 'create'
  createMode?: 'list' | 'card'     // 新增视图模式
  formulaConfig?: FormulaConfig     // 公式配置
  listActions?: ListAction[]        // 列表级操作按钮
  migrations?: SchemaMigration[]    // Schema 迁移脚本
  status: 'active' | 'disabled' | 'error'
}
```

### 5.2 FieldSchema（字段定义）

```ts
interface FieldSchema {
  id: string
  name: string
  key: string                       // 字段标识（映射到记录字段）
  type: FieldType                   // 字段类型（见下方）
  label: string                     // 显示标签
  required: boolean
  readonly: boolean
  order: number                     // 排序
  visible: boolean
  width?: number                    // 列宽
  fixed?: 'left' | 'right'         // 固定列
  sortable: boolean
  filterable: boolean
  defaultValue?: unknown
  validationRules?: ValidationRule[]
  permission?: FieldPermission      // 字段级权限
  formula?: FormulaFieldConfig      // 公式配置
  dynamicMax?: DynamicMaxConfig     // 动态最大值
  options?: SelectOption[]          // select/multi-select 选项
  targetModule?: string             // FK 目标模块
  displayField?: string             // FK 显示字段
  previousKeys?: string[]           // 历史字段名（迁移映射）
  relationConfig?: RelationConfig   // 一对多/多对多关联
```

## 6. Mock 模式（开发/演示）

### 6.1 快速启动 Mock

```ts
import { initMockServices, resetAllStorage } from 'schemagine'

// 初始化所有 Mock Service
initMockServices()

// 重置所有 Mock 数据（localStorage）
resetAllStorage()
```

### 6.2 Mock 数据持久化

Mock 模式将数据存储在 `localStorage` 中（key 前缀 `schemagine:`），刷新页面后数据保持。调用 `resetAllStorage()` 可清空所有数据恢复初始状态。

### 6.3 Mock 与真实 Service 混合使用

可以只 Mock 部分 Service，其余对接真实后端：

```ts
import { initMockServices, setMockEnabled } from 'schemagine'

// 仅 Mock SchemaService，RecordService 对接后端
import { MyRecordService } from './services/MyRecordService'

initMockServices()     // 初始化所有 Mock
setRecordService(new MyRecordService())  // 覆盖 RecordService
```

### 6.4 自定义 Mock 模块

参考内置示例添加你自己的 Mock Schema 和种子数据：

```ts
  ],
```

## 7. 组合式函数（Composables）

```vue
<script setup lang="ts">
import { useSchemaMeta, useRecords, useUi } from 'schemagine'

const schemaMeta = useSchemaMeta()     // Schema & 配置

</script>
```

### 7.2 创建独立状态实例

```ts
import { createSchemaMetaState, createRecordState, createUiState } from 'schemagine'

const meta = createSchemaMetaState()
const recordState = createRecordState()
const uiState = createUiState()
```

```
│  └──────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
         │
         ▼ Service 层（注入接口）
┌──────────────────────────────────────────────────────┐
│  IRecordService    ← 记录 CRUD                        │
│  ISchemaService    ← Schema & 权限                    │
│  ICandidateService ← FK 候选值查询                     │
│  IUserViewConfigService ← 视图配置持久化                │
│  IRelationService  ← 关联关系管理                      │
└──────────────────────────────────────────────────────┘
         │
         ▼ 你的实现
┌──────────────────────────────────────────────────────┐
│  API 调用 / 数据库 / 第三方服务                         │
└──────────────────────────────────────────────────────┘
```

### 8.2 数据流

```
UI 操作 → Composable（逻辑层）→ Service（API 层）→ 后端
                ↓
        状态更新（响应式）
                ↓
        视图自动刷新
```

### 8.3 关键设计决策

| 决策 | 说明 |
|------|------|
| **Service Injection** | 引擎不耦合业务 API，通过接口注入实现 |
| **Schema-Driven** | 所有视图由 Schema 配置驱动，无需手写模板 |
| **乐观锁** | 写操作携带 `version`，冲突时自动重试 |
| **多实例隔离** | `create*State()` 工厂函数确保每个实例独立 |
| **ErrorBoundary** | 渲染异常不扩散，仅影响当个实例 |
| **服务降级** | Service 未初始化时返回 Fallback 而非崩溃 |

## 10. FAQ / 常见问题

### Q1：引擎会与宿主应用的状态冲突吗？

不会。引擎通过 `createSchemaMetaState()` / `createRecordState()` / `createUiState()` 函数创建独立的实例，并通过 Vue 的 `provide/inject` 进行隔离。**Pinia Store 也是动态注册的**，多个 `SchemaEngine` 实例之间互不干扰。

### Q2：如何替换默认的 UI 组件？

引擎的所有 UI 基于 Element Plus + vxe-table。你可以在自己的项目中：
- 覆盖 Element Plus 主题变量（CSS Variables）
- 使用 `FieldEditorFactory` + `ValueRenderer` 搭配自己的组件
- 完全替换视图层（使用 `useSchemaMeta()` / `useRecords()` 消费状态）

### Q3：如何处理权限？

权限分两层：
1. **模块级权限**（`ModulePermissions`）：由 `ISchemaService.loadModulePermissions()` 返回
2. **字段级权限**（`FieldPermission`）：定义在 `FieldSchema.permission` 中

引擎自动根据权限控制 UI 的显示/编辑状态。你还可以通过 `usePermission()` composable 在自定义组件中检查权限。

### Q4：表格大数据量性能如何？

表格基于 `vxe-table`，支持：
- 虚拟滚动（万级数据流畅）
- 列拖拽排序
- 列固定
- 自定义列宽

### Q5：Schema 变更后旧数据怎么办？

使用 Schema 迁移机制：
1. 在 `ModuleSchema.migrations[]` 中定义迁移脚本（`fromVersion` → `toVersion`）
2. 引擎在加载数据时自动执行迁移
3. 字段重命名使用 `FieldSchema.previousKeys[]`，旧 key 数据自动映射到新 key

### Q6：构建产物包含哪些内容？

```
dist/
├── schemagine.mjs        # ESM 格式（适用于现代打包器）
├── schemagine.cjs        # CJS 格式（适用于 Node.js require）
├── schemagine.css        # 引擎样式
├── index.d.ts            # 类型定义入口
└── ...                    # 各模块 .d.ts 文件
```

参考项目根目录的 `说明文档.md` 和 `.trae/rules/project_rules.md`，包含完整的开发规范和协作流程。
