> 评估基准：能否脱离当前 Demo 环境，直接作为 npm 包或通用组件库投入第三方项目使用。

## 一、组件通用性逐项评级

评级标准：🟢 解耦良好 / 🟡 局部耦合可改进 / 🔴 强耦合需重构

### 1.1 引擎核心层

| 组件 | 评级 | 说明 |
|------|------|------|
| **SchemaEngine** | 🟡 | Props 设计合理（moduleId/embedded/readonly），但内部直接 import 所有 composables + stores，无法替换。缺少 `customServices` 注入 prop |
| **ViewContainer** | 🟢 | 纯布局组件，仅依赖 slot，完全通用 |
| **SchemaContextProvider** | 🟢 | provide/inject 模式良好，接口清晰可扩展 |
| **GlobalDialogHost** | 🟡 | 弹窗类型硬编码在内部 `dialogTitle` Map 中，新增弹窗需改源码 |

### 1.2 视图容器层

| 组件 | 评级 | 说明 |
|------|------|------|
| **ListView** | 🔴 | 直接 import `recordService` + `useRecordStore` + `useUiStateStore`，无法脱离 Pinia 环境。筛选/排序/分页逻辑耦合在组件内，不可独立复用 |
| **CardView** | 🟡 | 相对简洁，但直接依赖 `useRecordStore` + `useSchemaMetaStore` |
| **CreateView** | 🔴 | 最复杂组件，内联了列设置、聚合计算、FK 标签解析、草稿生命周期等 500+ 行逻辑。与 `useDraftLifecycle` / `useFormula` 紧耦合 |
| **CardCreateView** | 🔴 | 与 CreateView 有 ~60% 逻辑重复（公式展开、字段更新、defaults），未抽取共享逻辑 |

### 1.3 表格组件

## 二、待完善的架构方向

### 2.1 🔴 多实例隔离（阻塞级）

**问题**: `useSchema.ts` 中 `loadingModuleId` 是模块级全局 ref。同一页面嵌入两个 `SchemaEngine` 实例时，第二个实例的 `loadModule` 会覆盖第一个的 `loadingModuleId`，导致第一个实例的异步请求被错误丢弃。

**方案**: 将 `loadingModuleId` 移入 Store 或 composable 作用域内，按实例 ID 隔离。

### 2.2 🔴 编辑器插件化（阻塞级）

**问题**: `FieldEditorFactory.vue` 的 `editorComponent` computed 中类型映射表硬编码。第三方无法注册自定义字段编辑器。

**方案**: 提供 `registerFieldEditor(type, component)` API，`factory` 从注册表动态查找。

```typescript
// 期望的扩展接口
import { registerFieldEditor } from 'schemagine'
registerFieldEditor('custom-slider', MySliderEditor)
```

### 2.3 🟡 UI 库解耦（重要级）

**问题**: 全局直接 import Element Plus（`ElButton`、`ElMessage`、`ElDialog` 等）。切换到 Ant Design / Naive UI 需要改动 30+ 文件。

**方案**: 抽取 UI 适配层（类似 `VxeTableWrapper` 隔离 vxe-table），所有 UI 组件通过适配器调用。

### 2.4 🟡 国际化 i18n（重要级）

**问题**: 所有中文文案硬编码在模板和脚本中（"保存"/"取消"/"编辑"/"无权限"/错误消息等）。英文环境下完全不可用。

**方案**: 引入 vue-i18n 或自定义 i18n composable，所有文案改为 key 引用。

### 2.5 🟡 主题/设计令牌（重要级）

**问题**: 样式硬编码（`#e4e7ed`、`#909399`、`#303133` 等），无法换肤。CSS 变量使用不系统。

**方案**: 建立 CSS 变量设计令牌体系（`--sc-color-border`、`--sc-color-text-secondary` 等），提供亮/暗主题。

### 2.6 🟡 视图模块可替换性（重要级）

**问题**: `ListView` / `CardView` / `CreateView` 直接硬编码在 `SchemaEngine` 模板中。无法替换为自定义视图。

**方案**: 提供 slot 或 prop 注入自定义视图组件。

### 2.7 🟢 包发布准备（增强级）

**问题**: 当前无 `build` 输出为库的配置，vite.config.ts 仅配置了 app 构建。

**方案**: 添加 library mode build，输出 ESM + CJS + .d.ts，配置 `package.json` exports 字段。

## 五、架构亮点（值得保留发扬）

1. **Service 接口注入模式** — 接口与实现分离，前后端切换零代码改动
2. **FieldEditorFactory 工厂模式** — 类型→组件映射表，扩展性好（待插件化）
3. **SchemaContextProvider provide/inject** — 依赖注入，避免 props 层层传递
4. **10 种 FilterOperator 标准化协议** — 筛选语法自描述，前后端统一解析
5. **乐观锁 + 撤销栈** — 并发安全 + 操作可逆
6. **16 列 CSS Grid 卡片布局** — 响应式降级，字段级 span 可配
7. **类型系统分层** — schema/record/service/events/config 职责清晰
8. **mathjs 公式引擎** — 拓扑排序 + 循环检测 + 精度控制
